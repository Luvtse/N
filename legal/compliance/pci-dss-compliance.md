# NIDAW PCI DSS Compliance Statement

## 1. Commitment
NIDAW Inc. is committed to protecting cardholder data in accordance with the Payment Card Industry Data Security Standard (PCI DSS) v4.0.

## 2. Compliance Level
NIDAW is a **PCI DSS Level 1** service provider (highest level), processing over 6 million transactions annually.

## 3. Scope
This compliance applies to:
- Payment processing infrastructure.
- Cardholder data environment (CDE).
- Related systems and personnel.

## 4. Security Controls
NIDAW implements the following PCI DSS requirements:
- **Requirement 1:** Install and maintain a firewall configuration.
- **Requirement 2:** Do not use vendor-supplied defaults.
- **Requirement 3:** Protect stored cardholder data (encryption, tokenization).
- **Requirement 4:** Encrypt transmission of cardholder data (TLS 1.3).
- **Requirement 5:** Protect all systems against malware.
- **Requirement 6:** Develop and maintain secure systems.
- **Requirement 7:** Restrict access to cardholder data.
- **Requirement 8:** Identify and authenticate access.
- **Requirement 9:** Restrict physical access.
- **Requirement 10:** Track and monitor all access.
- **Requirement 11:** Regularly test security systems.
- **Requirement 12:** Maintain an information security policy.

## 5. Auditing
NIDAW undergoes annual PCI DSS audits by a Qualified Security Assessor (QSA). The latest Attestation of Compliance (AOC) is available upon request.

## 6. Tokenization
NIDAW uses tokenization to replace card numbers with unique tokens. Actual card data is stored only by our PCI-compliant payment processors (Stripe, Adyen).

## 7. Incident Response
NIDAW maintains a PCI-compliant incident response plan. In the event of a breach:
- Contain the incident.
- Notify affected parties.
- Notify payment brands.
- Conduct forensic investigation.
